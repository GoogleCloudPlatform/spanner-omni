{{- $monitoring := $.Values.monitoring | default dict }}
{{- $usesBundledJaeger := and $monitoring.enabled (not $.Values.deployment.traceExporterEndpoint) }}
{{- $jaegerTls := dig "jaeger" "tls" "enabled" false $monitoring }}
{{- /* First Spanner Omni release that exports traces over TLS. */}}
{{- $minTlsTraceRelease := "2026.r4-lts.3" }}
{{- if and (not $.Values.global.insecureMode) $usesBundledJaeger (not $jaegerTls) }}
[WARNING] Traces will NOT be exported in secure mode!
Spanner Omni is running in secure mode (global.insecureMode=false) and exports
traces to the bundled Jaeger (monitoring.enabled=true with an empty
deployment.traceExporterEndpoint), but Jaeger's OTLP gRPC receiver does not
serve TLS (monitoring.jaeger.tls.enabled=false). In secure mode, Spanner only
exports traces to a remote OTLP endpoint over TLS, so all traces are dropped.

To fix this:
  1. Create a TLS Secret named {{ dig "jaeger" "tls" "secretName" "jaeger-tls" $monitoring | quote }} (keys tls.crt and tls.key) in
     the {{ $monitoring.namespace | default "monitoring" | quote }} namespace. The certificate's SANs must include
     jaeger.{{ $monitoring.namespace | default "monitoring" }}.svc.cluster.local.
  2. Add the CA certificate that signed it to the `tls-certs` Secret in the
     {{ include "spanner-omni.namespace" . | quote }} namespace under the key `ca-otlp.crt`.
  3. Upgrade the release with --set monitoring.jaeger.tls.enabled=true.
  4. Restart the Spanner servers: they only start using `ca-otlp.crt` after a
     restart if it was added while they were running.
{{- end }}
{{- if and $monitoring.enabled $jaegerTls }}

[NOTE] The bundled Jaeger only accepts traces over TLS (monitoring.jaeger.tls.enabled=true).
Spanner Omni sends traces to it in plaintext, which Jaeger rejects (so all traces are lost),
unless all of the following hold, in secure and insecure mode alike:
  1. The `tls-certs` Secret in the {{ include "spanner-omni.namespace" . | quote }} namespace contains `ca-otlp.crt`, the
     CA that issued Jaeger's certificate. Use a dedicated CA, not the internal `ca.crt`.
  2. The Spanner Omni servers run release {{ $minTlsTraceRelease }} or later (2026.r5 does not support it).
  3. The Spanner Omni servers were restarted after `ca-otlp.crt` was added, for example:
       kubectl rollout restart statefulset -n {{ include "spanner-omni.namespace" . }} -l app.kubernetes.io/instance={{ $.Release.Name }}
{{- end }}
